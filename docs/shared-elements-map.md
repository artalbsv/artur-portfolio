# Shared Elements Map

## Persistent visual grammar

The experience uses one family of elements that changes function rather than introducing a new decorative system in every section.

| Element | Identity | Project Stage | Capability System | Lab | Contact |
| --- | --- | --- | --- | --- | --- |
| Coordinate field | Quiet horizon and origin point | Browser/device construction grid | Discipline-specific diagram | Procedural input field | Collapses into final rule |
| Primary frame | Hero object boundary | Desktop browser | Interface viewport | Lab portal | Email boundary |
| Red signal | Current coordinate | Active project number | Active discipline | Live input indicator | Focus/hover only |
| Media plane | Spatial object surface | Project screenshot | Contextual proof fragment | Experiment surface | Removed for release |
| Mono metadata | Location/status | Role, period, outcome | Experience, education, languages | System name and input | Availability/time |

## Project Stage continuity

### Rodociclo → Bike Tech

1. Rodociclo desktop fills the primary browser frame.
2. The browser contracts and shifts off-axis.
3. A mobile viewport emerges from the same frame edge.
4. The media source changes only after the geometry establishes continuity.
5. Bike Tech settles with the mobile device as dominant and desktop as supporting evidence.

### Bike Tech → Visual & Motion

1. The device screen separates into proportion-aware media planes.
2. Planes rotate into a short editorial strip.
3. The selected visual/media item becomes dominant while neighboring work remains discoverable.
4. Clicking any plane opens the existing full-ratio viewer.

### Visual & Motion → Experiments

1. Media edges simplify into technical line segments.
2. The line segments become the coordinate system for a procedural signal.
3. The signal resolves into the Lab entry surface.

## Route continuity

- Project state links keep `data-page-transition` metadata and pass the current media source into the existing page-transition layer.
- The selected stage frame is the visual origin of the route transition.
- Returning to `/#work` restores a predictable stage entry instead of landing in an unrelated section.

## Mobile adaptation

- Shared elements retain identity, not desktop geometry.
- Browser and device are placed in a single visual frame; no overlap is required to communicate continuity.
- State changes use a short horizontal displacement and content swap.
- Swipe is optional support; visible buttons remain primary.

## Reduced motion adaptation

- Geometry snaps between stable layouts.
- No persistent drift, parallax or route expansion.
- State hierarchy and media continuity remain visible through composition alone.
